# 문서 작성 및 Git 워크플로우 가이드

이 문서는 프로젝트에서 마크다운(.md) 문서를 작성하고, Git을 통해 안전하게 협업하는 과정을 설명합니다. Git을 처음 사용하시는 분들도 차근차근 따라 하실 수 있도록 단계별로 구성되었습니다.

---

## 1. 문서 작성하기

문서 작업은 주로 마크다운 형식을 사용합니다. 

문서 위치는 항상 **document/** 에 위치하여 있습니다

* **도구 준비**: [옵시디언(Obsidian)](https://obsidian.md/) 또는 선호하는 마크다운(Markdown) 에디터(VS Code 등)를 실행합니다.
* **문서 작성/수정**: 프로젝트 폴더 내의 `.md` 파일을 열어 내용을 자유롭게 작성하거나 수정합니다. 저장(`Ctrl + S` 또는 `Cmd + S`)하는 것을 잊지 마세요!

---

## 2. Git으로 작업 내용 공유하기 (Pull Request)

문서 작성이 끝났다면, 내가 작업한 내용을 팀의 메인 코드베이스에 반영해 달라고 요청해야 합니다. 이 과정을 **Pull Request(PR)** 라고 부릅니다. 

아래 명령어들을 터미널(또는 Git Bash)에 순서대로 입력해 주세요.

### 단계 2-1. 최신 상태 맞추기
항상 최신 코드를 바탕으로 작업을 시작해야 충돌을 방지할 수 있습니다. 기준이 되는 `develop` 브랜치로 이동하여 최신 내용을 받아옵니다.

```bash
# 1. develop 브랜치로 이동
git checkout develop

# 2. 원격 저장소의 최신 변경사항을 내 컴퓨터로 가져오기
git pull origin develop
```

### 단계 2-2. 나만의 작업 공간(브랜치) 만들기
안전한 작업을 위해 `develop`에서 갈라져 나온 나만의 독립된 공간(브랜치)을 만듭니다. 브랜치 이름은 임의로 자유롭게 지어주시면 됩니다.

```bash
# 새 브랜치를 만들고 동시에 그 브랜치로 이동하기
git checkout -b <원하는_브랜치_이름>

# (예시) 문서 작성을 위한 브랜치 이름
# git checkout -b docs/my-new-document
```

### 단계 2-3. 변경사항 저장하기 (Commit)
내가 수정한 파일을 Git이 추적하도록 추가하고(add), "어떤 작업을 했는지" 메모와 함께 확정(commit) 짓는 과정입니다.

```bash
# 1. 변경된 모든 파일을 저장할 준비(스테이징) 하기
git add .

# 2. 작업 내용을 메모와 함께 저장하기
git commit -m "어떤 문서를 수정/추가했는지 알아보기 쉽게 작성합니다"

# (예시)
# git commit -m "docs: 문서 작성 플로우 가이드 업데이트"
```

### 단계 2-4. 원격 저장소에 내 브랜치 올리기 (Push)
내 컴퓨터(로컬)에만 저장된 작업 내역을 GitHub 원격 저장소에 업로드합니다.

```bash
# 내가 만든 브랜치를 원격 저장소에 올리기
git push origin <원하는_브랜치_이름>

# (예시)
# git push origin docs/my-new-document
```

### 단계 2-5. Pull Request (PR) 생성하기
이제 코드를 합쳐달라고 요청할 차례입니다!

1. GitHub 웹사이트에 접속하여 프로젝트 레포지토리로 들어갑니다.
2. 방금 올린 브랜치에 대해 노란색/초록색 알림창과 함께 **`Compare & pull request`** 버튼이 나타나면 클릭합니다.
3. PR 생성 화면에서 다음 두 가지가 올바르게 설정되어 있는지 반드시 확인합니다.
   * **base**: `develop` (코드가 합쳐질 도착지)
   * **compare**: `<원하는_브랜치_이름>` (내가 작업한 출발지)
4. 제목과 내용을 팀원들이 알아보기 쉽게 적어줍니다.
5. **`Create pull request`** 초록색 버튼을 클릭하면 완료됩니다! 🎉
